# Navigation Policy

This repo contains **source Guides (Markdown)** and **published Guides (HTML)**.

## Source vs published
- **Source Markdown (authoring):** `guides/*.md`
- **Published HTML (GitHub Pages output):** `docs/guides/*.html`

Do not manually edit published HTML unless you are debugging output.
Make changes in `guides/*.md` and regenerate.

## Where navigation comes from
The Guides navigation is generated by:
- `scripts/build-guides.mjs`

That script:
- Reads the Markdown files in `guides/`
- Builds HTML pages into `docs/guides/`
- Builds `docs/guides/index.html` and the left nav

## Adding a new Guide page
1. Create a new Markdown file in `guides/` (example: `rate-limits.md`)
2. Add the page to the Guides nav in `scripts/build-guides.mjs`
   - Keep the title short and task-focused
3. Regenerate the HTML output
4. Verify links in:
   - `docs/guides/index.html`
   - the left nav on a couple pages
5. Commit both:
   - the source Markdown
   - the regenerated HTML output (if your repo publishes built HTML)

## Meta/lifecycle links
The following links are treated as “Meta” docs and should appear in Guides navigation:
- Release notes (v2.0): `docs/release-notes/v2.0.md`
- Migration (v1 → v2): `docs/migration/v1-to-v2.md`
- Verification checklist: `docs/verification/v2.0-verification.md`

These links should:
- Use canonical GitHub URLs (stable, reviewable)
- Or use GitHub Pages URLs if you publish Markdown rendering elsewhere

## When to update the repo root docs hub
If you change Guides structure, also update:
- Repo `README.md` (entry links)
- `docs/index.html` (published hub page), if you maintain one

## Definition of done for nav changes
- New page is reachable from Guides index and the left nav
- No broken links
- Page titles match nav labels
- Generated HTML is committed (if the repo hosts built output)
